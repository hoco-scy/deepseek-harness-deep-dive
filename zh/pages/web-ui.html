Web UI 插件架构

客户端 Cordis、Slot、SessionRuntime 与会话投影

已复核上游 47f943859b范围: 分析宿主/浏览器双面插件、模块装载、slots、conversation nodes、工具展示、重连与状态所有权。

结论：Web UI 是第二棵受治理的插件树，React 只是最后一公里

DeepSeek Harness 的浏览器端不是一组被 Host 直接打包进页面的 React 组件。Host Cordis 树先从当前 Loader 组合计算客户端插件图、提供带内容 revision 的 bundle，并把 manifest 写进 HTML；页面再创建一棵独立的浏览器 Cordis 树，用同一份图装载插件。业务状态停在 React-free 的 ConnectionController、SessionManager、Session、SlotRegistry 与 ConversationNodeAssembler 中，web-react 把裸 observable 绑定成 hooks、合成终端 props，最终由一个 root Slot 进入 React。

这套架构把“代码怎样到达浏览器”“插件何时有权贡献界面”“断线后什么需要重取”“一个会话的视图状态何时死亡”分成不同协议。其价值不只是可插拔：动态包可以在不让 Shell 知道业务清单的前提下声明位置、状态和能力；代价则是启动、授权、scope 与重放边界都必须保持一致，否则系统会选择显式失败，而不是悄悄渲染一棵半有效的树。

1. 两棵 Cordis 树：Host 决定可到达代码，Browser 决定活的对象

Web bundle 的 Host 配置同时列出普通 Host 服务（API proxy、runner、webserver）和带 dsh.client 的浏览器插件 roster；其中 modules 是明确的双面包：Node half 扫描 Host Loader 树并发布图，browser half 则成为页面内模块表。connection、runtime、theme、locale、layout、conversation 与 tool 都是图中的独立客户端 entry。WEBUI-DUAL-ROSTER

ClientModuleRegistry 在 Host 上订阅 Loader fiber 变化，初次激活与增量变动走同一条扫描路径；它只接纳仍有 fiber、未 disabled 且声明 web client 的 entry，注册 /plugins 路由，并用 index tap 注入当前 graph。WEBUI-HOST-GRAPH页面端则解析该 graph、构造自己的 Context，再启动浏览器 Loader；这不是把 Host context 序列化到页面，而是 Host 交付组成事实、Browser 重建生命周期。WEBUI-BROWSER-CONTEXT

推论

信任边界因此是双层的：Host 决定哪些包可被页面取到，Browser 的 Cordis fiber 再决定它们是否满足依赖、是否激活、何时卸载。manifest 是组成协议，不是运行中 service container 的远程镜像。

2. Manifest 与两阶段启动：代码到达不等于插件激活

每个 graph row 带 id、bundle url、内容 rev、信息性 inject 边以及可选 immediately。entry 顺序明确不承载激活语义；真正的依赖顺序由 Cordis fiber 的 inject waiting 决定。wire 在浏览器边界完成行字段形状校验后，拆成 module view 与 plugin view。WEBUI-MANIFEST-CONTRACT

阶段动作提交条件

边界：immediately 只是“提前让 factory 到达”的性能层级，不是更高权限，也不改变插件依赖图。

3. 动态模块表与 HMR：先替换代码，再替换 fiber

ClientModuleSystem 使用惰性 CJS 表：外部 classic script 调用 window.__ModuleLoader__.load 只登记 factory；第一次 import 或同步 require 才执行 factory，并缓存 exports、依赖边与它注入的样式。同步 require 只能命中平台 seed、shell static、cache 或已登记 factory，不能临时发起网络请求；循环依赖和未知模块都会显式报错。WEBUI-LAZY-MODULES

Host HMR 端以默认 500ms stat poll 观察 graph 中每个 bundle，内容 hash 真正变化后更新 graph revision，并通过 /plugins/events SSE 广播 rebuilt；连接时还发送 graph snapshot。WEBUI-HMR-HOSTBrowser 端把 reload 串行化：invalidate → prefetch 在旧 fiber 仍服务时取得新 factory，然后先删 registry runtime、排空旧 fiber、移除 owned styles、清除 entry.fiber，最后 entry.refresh() 重新 materialize 与 apply。失败不回滚旧 bundle；prefetch 早期失败时旧 fiber 还在，apply 失败则留下 FAILED fiber。WEBUI-HMR-SWAP

取舍

HMR 的一致性单位是插件 fiber，不是 React component。这样 service provider 替换会通过 Cordis activation epoch 自然级联到依赖者，避免 HMR 自己维护第二张依赖图；相应地，重载插件内部的 React local state 不被保留。

4. Shell 极薄：只安装 renderer，并渲染一个 root

app-shell entry 等待 slots、sessions、layout，安装由 web-react 提供的 Slot renderer，并暴露 identity-stable 的 renderApp closure。WEBUI-SHELL-INSTALL真实 assembly 除了会话标题投影，只做一次 ctx.slots.renderSlot('root', {})；AppFrame、sidebar、conversation、details 与 overlay 均由后续注册形成。WEBUI-SHELL-ROOT

事实

Shell 不枚举业务页面，也不 import 每个 UI package。它知道的是启动状态、renderer contract 和根 Slot；具体 surface roster 来自 Host graph，具体树形来自 Slot declarations。

5. React-free 对象层：连接、会话与投影先成立，组件随后订阅

runtime 插件先创建 SlotRegistry、Conversation event/view registries、SessionRuntime 和 WorkspaceRuntime，再由唯一消费者启动 connection streams。Mux 帧进入 sessions，Host 帧同时进入 sessions/workspaces，通用 remote event 则转交 remote dispatch；连接建立和死亡只调用对象层方法。WEBUI-RUNTIME-WIRING

6. WebSocket 重连：重建代际，不假装续接旧流

每个 ConnectionController generation 同时打开 mux 与 host 两条 downlink，并并发执行 host.describe。describe 必须成功；stream readiness 通常等待两条 onOpen，但 3s carrier-open 防楔死 guard 超时后也会放行。readiness 收敛后，stream 结束或 stream/error 会 abort 整代，进入带 jitter 的指数退避，随后创建新 generation。业务 sink 抛错被隔离，不能拖垮 pump。但 host.describe 自身没有 generation signal 或 timeout：若它永久挂起，即使 stream 已结束，控制流仍卡在 handshake 的 Promise.all，不能进入共享重连路径。WEBUI-CONNECTION-GENERATION

runtime 在 generation 死亡时先清除仅对旧连接有效的 pending interactions；新代 ready 后刷新 Session 与 Workspace baseline、发出 connection/reset。WEBUI-RUNTIME-RECONNECTSessionManager 还会重新拉会话列表与已打开的 subagent catalogs，并对所有 resident Session 调用 resync()。WEBUI-MANAGER-RECONNECT从未 open 的 cold resident 在此路径 no-op。WEBUI-SESSION-RESYNC

事实

refreshList() 是 single-flight；请求开始后到达的 live mutations 会重放在响应 baseline 之上。因此“重取”不是用一个较旧列表覆盖重连期间已经观察到的状态。WEBUI-LIST-REFETCH

7. 冷会话、refetch 与 seq gap repair 是三种不同路径

SessionManager 不会因为任意 mux frame 就创建 Session。未实例化会话的普通 event 被丢弃，日后 open() 由 history 回填；需要随 Session 重放的 pending buffer 只保留 history 不能恢复的 approval、question 和最新 queue snapshot。projection 与 jobs 则落在 manager 级镜像，不触发 Session 创建。WEBUI-COLD-SESSION-DISPATCHSession 实例在真正解析 scope 时才惰性创建并重放 pending buffer。WEBUI-LAZY-SESSION

8. SlotRegistry：children 声明同时是结构、规格与渲染授权

SlotMap 给每个位置定义 kind、scope 与 owner props；一个 registration 的 children 表不仅记录子 Slot 的 runtime spec，还声明“此 entry 是唯一可渲染这些 key 的主体”。WEBUI-SLOT-TYPE-CONTRACTSlotCore 只先验声明 root。注册未声明目标、重复声明 child、kind 参数缺失或同一 shared store handle 跨 scope 都在 load time 抛错。WEBUI-SLOT-CORE-COMMIT成功提交后，entry disposer 会递归坍缩它声明的整棵子树。WEBUI-SLOT-CASCADE

ctx.slots.inject(key, callback) 让独立激活的贡献者等待声明出现：声明已经存在就同步运行；声明坍缩就逆向处置；之后重新声明则按新的 epoch 再运行。controller 与 callback effect 都归调用方 fiber，因此卸载贡献插件既能取消等待，也能移除已激活注册。WEBUI-SLOT-DECL-INJECT

ui-layout 对 root 的一次注册同时声明 sidebar、conversation、details 与 shell.overlay，并挂入 layout store 与 business inject。WEBUI-ROOT-DECLARATION这说明 layout 不是硬编码 import 树，而是第一位拥有子位置授权的 registrant。

10. web-react 是 binding terminal，不是业务 runtime

bindSnapshotSelector() 是客户端栈统一的通用 selector-hook constructor：把任何 getSnapshot/subscribe source 绑定成 useSyncExternalStoreWithSelector hook，并稳定捕获 source methods。WEBUI-REACT-BINDINGrenderer 在 entry 渲染时合成 global/session hooks、projection hook、store pair、授权后的 renderSlot、SessionProvider 与 locale t；runtime 交到这条组合边界的仍是裸 source。WEBUI-RENDER-KIT

保留的 renderSlot closure 还会在每次调用时检查 entry 是否仍在 ledger、目标 key 是否由其 children 声明；卸载后的旧 closure 或越权 key 都会抛出专用错误。WEBUI-STALE-AUTHORIZATION

推论

React 负责订阅一致性与组件隔离，SlotCore 负责组合事实，Session/Store 负责状态事实。把 hooks 限制在 terminal 层，使 HMR、测试和非 React 消费者不需要模拟组件生命周期才能保持业务对象正确。

12. Session scope：选择负责 staging，解析负责惰性对象，prune 统一回收

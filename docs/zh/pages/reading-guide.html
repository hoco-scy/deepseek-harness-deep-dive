先掌握三个不变量

源码事实

模型 adapter、工具注册表、session log、agent loop 都作为插件挂入共享 Cordis context；仓库明确宣称不存在必须被 patch 的特权核心。ARCH-PLUGIN-CORE

源码事实

任何真正进入模型请求的内容都必须能从 session log 重建。日志因此不仅服务 UI 展示，也是模型上下文、恢复、fork、遥测和重放的共同事实源。ARCH-LOG

机制推导

DeepSeek Harness 的“核心”不是某个稳定不变的循环类，而是一组更难被替换的系统不变量：作用域、事件顺序、可逆注册、模型可见输入的日志化，以及能力定义/提供者/消费者三方闭合。具体插件可替换，但这些组合语义构成了事实上的架构宪法。

推荐阅读路径

  1. 第一次阅读：设计哲学 → Turn/Step/Loop → 提示词 → 会话事件 → 工具管线。
  2. 关注 Agent 平台：持久化 → checkpoint → 压缩 → Plan/Goal/Todo → 多 Agent → Workflow。
  3. 关注安全执行：工具原语 → 权限审批 → Sandbox/FS → Shell/Terminal/Jobs → 安全模型。
  4. 关注工程质量：可观测与重放 → API/SDK/ACP → 测试与不变量 → 设计取舍。
  5. 反向查找：术语与证据目录 → 证据 ID、Package、路径、已文档化符号、持久化事件、实时事件或 Host Service。

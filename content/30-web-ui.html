结论：Web UI 是第二棵受治理的插件树，React 只是最后一公里

DeepSeek Harness 的浏览器端不是一组被 Host 直接打包进页面的 React 组件。Host Cordis 树先从当前 Loader 组合计算客户端插件图、提供带内容 revision 的 bundle，并把 manifest 写进 HTML；页面再创建一棵独立的浏览器 Cordis 树，用同一份图装载插件。业务状态停在 React-free 的 ConnectionController、SessionManager、Session、SlotRegistry 与 ConversationNodeAssembler 中，web-react 把裸 observable 绑定成 hooks、合成终端 props，最终由一个 root Slot 进入 React。

这套架构把“代码怎样到达浏览器”“插件何时有权贡献界面”“断线后什么需要重取”“一个会话的视图状态何时死亡”分成不同协议。其价值不只是可插拔：动态包可以在不让 Shell 知道业务清单的前提下声明位置、状态和能力；代价则是启动、授权、scope 与重放边界都必须保持一致，否则系统会选择显式失败，而不是悄悄渲染一棵半有效的树。

1. 两棵 Cordis 树：Host 决定可到达代码，Browser 决定活的对象

Web bundle 的 Host 配置同时列出普通 Host 服务（API proxy、runner、webserver）和带 dsh.client 的浏览器插件 roster；其中 modules 是明确的双面包：Node half 扫描 Host Loader 树并发布图，browser half 则成为页面内模块表。connection、runtime、theme、locale、layout、conversation 与 tool 都是图中的独立客户端 entry。

Host Cordis tree
  Loader entries ──scan dsh.client──► manifest + /plugins bundles
          │                                  │
          └── webserver / API / SSE          ▼
                                      window.__DSH_BOOT__
                                               │
Browser Cordis tree                            ▼
  Context + Loader ◄── ClientModuleSystem ◄── manifest
          │
          └── connection → runtime → UI plugins → root Slot → React

ClientModuleRegistry 在 Host 上订阅 Loader fiber 变化，初次激活与增量变动走同一条扫描路径；它只接纳仍有 fiber、未 disabled 且声明 web client 的 entry，注册 /plugins 路由，并用 index tap 注入当前 graph。页面端则解析该 graph、构造自己的 Context，再启动浏览器 Loader；这不是把 Host context 序列化到页面，而是 Host 交付组成事实、Browser 重建生命周期。

推论

信任边界因此是双层的：Host 决定哪些包可被页面取到，Browser 的 Cordis fiber 再决定它们是否满足依赖、是否激活、何时卸载。manifest 是组成协议，不是运行中 service container 的远程镜像。

2. Manifest 与两阶段启动：代码到达不等于插件激活

每个 graph row 带 id、bundle url、内容 rev、信息性 inject 边以及可选 immediately。entry 顺序明确不承载激活语义；真正的依赖顺序由 Cordis fiber 的 inject waiting 决定。wire 在浏览器边界完成行字段形状校验后，拆成 module view 与 plugin view。

阶段动作提交条件
Module face并行 prefetch immediately rows；执行脚本只注册 factory所有 prefetch 尝试已结算；失败留给 entry import 显式报告
Plugin face先挂 Loader 并注入 module system，再并发创建 entriesLoader quiesced
UI gate扫描每个 entry 的 root fiber全部 ACTIVE 才从 loading 一次切换到完整 UI

启动实现先等待立即层 barrier，再创建 modules entry、manifest entries 和 shell-own app-shell entry；单项 prefetch 失败只在优化层被吞下，随后由 entry import 重试并显式呈现结果。loader.await() 之后还会完整扫描 fiber：无 fiber 表示 import 失败，PENDING 会列出缺失 service，FAILED 则保留失败状态；任何一个 entry 未激活都会让 loading 页面继续承载错误报告，不提供部分 UI。

边界：immediately 只是“提前让 factory 到达”的性能层级，不是更高权限，也不改变插件依赖图。

3. 动态模块表与 HMR：先替换代码，再替换 fiber

ClientModuleSystem 使用惰性 CJS 表：外部 classic script 调用 window.__ModuleLoader__.load 只登记 factory；第一次 import 或同步 require 才执行 factory，并缓存 exports、依赖边与它注入的样式。同步 require 只能命中平台 seed、shell static、cache 或已登记 factory，不能临时发起网络请求；循环依赖和未知模块都会显式报错。

Host HMR 端以默认 500ms stat poll 观察 graph 中每个 bundle，内容 hash 真正变化后更新 graph revision，并通过 /plugins/events SSE 广播 rebuilt；连接时还发送 graph snapshot。Browser 端把 reload 串行化：invalidate → prefetch 在旧 fiber 仍服务时取得新 factory，然后先删 registry runtime、排空旧 fiber、移除 owned styles、清除 entry.fiber，最后 entry.refresh() 重新 materialize 与 apply。失败不回滚旧 bundle；prefetch 早期失败时旧 fiber 还在，apply 失败则留下 FAILED fiber。

取舍

HMR 的一致性单位是插件 fiber，不是 React component。这样 service provider 替换会通过 Cordis activation epoch 自然级联到依赖者，避免 HMR 自己维护第二张依赖图；相应地，重载插件内部的 React local state 不被保留。

4. Shell 极薄：只安装 renderer，并渲染一个 root

app-shell entry 等待 slots、sessions、layout，安装由 web-react 提供的 Slot renderer，并暴露 identity-stable 的 renderApp closure。真实 assembly 除了会话标题投影，只做一次 ctx.slots.renderSlot('root', {})；AppFrame、sidebar、conversation、details 与 overlay 均由后续注册形成。

事实

Shell 不枚举业务页面，也不 import 每个 UI package。它知道的是启动状态、renderer contract 和根 Slot；具体 surface roster 来自 Host graph，具体树形来自 Slot declarations。

5. React-free 对象层：连接、会话与投影先成立，组件随后订阅

runtime 插件先创建 SlotRegistry、Conversation event/view registries、SessionRuntime 和 WorkspaceRuntime，再由唯一消费者启动 connection streams。Mux 帧进入 sessions，Host 帧同时进入 sessions/workspaces，通用 remote event 则转交 remote dispatch；连接建立和死亡只调用对象层方法。

WebSocket / HTTP
      │
ConnectionController       物理连接代际、backoff、frame pump
      │
SessionManager             实例目录、冷会话缓冲、列表与投影
      │
Session                    连续 seq window、pending、Conversation snapshots
      │
bare getSnapshot/subscribe sources
      │
web-react                  useSyncExternalStore selector hooks
      │
components

runtime 明确拥有 snapshot-store engine 并导出裸 observable；React binding 不反向进入 object layer。这使同一 Session 可以被非 React 观察者、Slot renderer 和测试消费，也把 connection generation、history repair 等业务状态排除在组件 mount/unmount 之外。

6. WebSocket 重连：重建代际，不假装续接旧流

每个 ConnectionController generation 同时打开 mux 与 host 两条 downlink，并并发执行 host.describe。describe 必须成功；stream readiness 通常等待两条 onOpen，但 3s carrier-open 防楔死 guard 超时后也会放行。readiness 收敛后，stream 结束或 stream/error 会 abort 整代，进入带 jitter 的指数退避，随后创建新 generation。业务 sink 抛错被隔离，不能拖垮 pump。但 host.describe 自身没有 generation signal 或 timeout：若它永久挂起，即使 stream 已结束，控制流仍卡在 handshake 的 Promise.all，不能进入共享重连路径。

runtime 在 generation 死亡时先清除仅对旧连接有效的 pending interactions；新代 ready 后刷新 Session 与 Workspace baseline、发出 connection/reset。SessionManager 还会重新拉会话列表与已打开的 subagent catalogs，并对所有 resident Session 调用 resync()。从未 open 的 cold resident 在此路径 no-op。

事实

refreshList() 是 single-flight；请求开始后到达的 live mutations 会重放在响应 baseline 之上。因此“重取”不是用一个较旧列表覆盖重连期间已经观察到的状态。

7. 冷会话、refetch 与 seq gap repair 是三种不同路径

SessionManager 不会因为任意 mux frame 就创建 Session。未实例化会话的普通 event 被丢弃，日后 open() 由 history 回填；需要随 Session 重放的 pending buffer 只保留 history 不能恢复的 approval、question 和最新 queue snapshot。projection 与 jobs 则落在 manager 级镜像，不触发 Session 创建。Session 实例在真正解析 scope 时才惰性创建并重放 pending buffer。

情况权威来源处理
从未打开的冷会话history + list baseline不维护 live window；打开时整页回填
重连后、此前已打开的 resident 会话新 generation baseline清空旧 window，generation-guarded resync()
已打开 window 中出现 seq > tail + 1history tail缓冲新帧并 repull；UI 保留旧 window，不闪 loading

Session 的首次 open 拉 history tail；若 session/subscribed.lastSeq 已超过 tail 且 live buffer 没覆盖缺口，会再拉一次。安装 window 后只按 seq 去重并 stitch buffer。运行中发现 hole 时进入 repairGap()：暂存后续帧、重拉 tail，再走同一安装路径；失败时不把有洞的序列直接追加到 UI。

8. SlotRegistry：children 声明同时是结构、规格与渲染授权

SlotMap 给每个位置定义 kind、scope 与 owner props；一个 registration 的 children 表不仅记录子 Slot 的 runtime spec，还声明“此 entry 是唯一可渲染这些 key 的主体”。SlotCore 只先验声明 root。注册未声明目标、重复声明 child、kind 参数缺失或同一 shared store handle 跨 scope 都在 load time 抛错。成功提交后，entry disposer 会递归坍缩它声明的整棵子树。

ctx.slots.inject(key, callback) 让独立激活的贡献者等待声明出现：声明已经存在就同步运行；声明坍缩就逆向处置；之后重新声明则按新的 epoch 再运行。controller 与 callback effect 都归调用方 fiber，因此卸载贡献插件既能取消等待，也能移除已激活注册。

ui-layout 对 root 的一次注册同时声明 sidebar、conversation、details 与 shell.overlay，并挂入 layout store 与 business inject。这说明 layout 不是硬编码 import 树，而是第一位拥有子位置授权的 registrant。

9. 四份 props share：所有权信息只在一个来源出现

Share来源组件获得什么
PropsRuntimeSlotMap 的 owner/key/scope/inject，以及父 registration 的 child spec父级 owner props、slot-level inject、global kit、按 scope 的 session kit
PropsRenderSlots本次注册的 children只允许渲染已声明 key 的 renderSlot；需要时附带 SessionProvider

术语边界：四份 share 是核心组合轴。当前 ComposedProps 还可按 registration 加入 chain 的 matched 与 locale 的 t 席位；它们不构成第五份业务所有权来源。

10. web-react 是 binding terminal，不是业务 runtime

bindSnapshotSelector() 是客户端栈统一的通用 selector-hook constructor：把任何 getSnapshot/subscribe source 绑定成 useSyncExternalStoreWithSelector hook，并稳定捕获 source methods。renderer 在 entry 渲染时合成 global/session hooks、projection hook、store pair、授权后的 renderSlot、SessionProvider 与 locale t；runtime 交到这条组合边界的仍是裸 source。

保留的 renderSlot closure 还会在每次调用时检查 entry 是否仍在 ledger、目标 key 是否由其 children 声明；卸载后的旧 closure 或越权 key 都会抛出专用错误。

推论

React 负责订阅一致性与组件隔离，SlotCore 负责组合事实，Session/Store 负责状态事实。把 hooks 限制在 terminal 层，使 HMR、测试和非 React 消费者不需要模拟组件生命周期才能保持业务对象正确。

12. Session scope：选择负责 staging，解析负责惰性对象，prune 统一回收

SessionRuntime 同时拥有列表投影、持久 selection、SessionManager、scope map 与当前 provide bundle；provider roster 改变时，即使 id 不变也会重建 provide bundle。dsh.sessions.current 只在启动时恢复候选选择，运行中的 selected 由 manager 保留；只有仍出现在 list items、或仍有 retained subagent address 的 selected id 才投影为 current。masked gap 会清除持久 cell，让 reload 留在空态，但同一进程里的选择在条目返回后仍可重新出现。

followCurrent() 把 stage 移到 current 并触发 idempotent history open；resolve() 才惰性创建 Cordis Agent scope、Session 对象、binding 与裸 provide sources。会话不再 eligible 且已离开 stage 时，统一 disposal scope fiber、解绑 Session、清除 session-keyed Slot stores，并从 manager 删除内存实例；若它在 staged 状态被移除，teardown 会延迟到 stage 移走，期间保留冻结 scope。Host Session log 始终是之后重新 open 回填的权威事实源。

Slot store instance 以 handle × scope key 缓存；root 用固定 key，session 用 session id。scope prune 还会清除对应 persisted value，防止已死亡会话留下孤儿 UI 状态。web-react 的根 provider 跟随 current；严格 SessionProvider 以 key={sessionId} 重挂整个 session subtree，确保跨会话 local component state 不串线。

13. Conversation Node：把日志折叠成业务 Context，再投影到多个视图

Conversation Definition 的 match(event) 只能看当前 event，返回稳定业务 id 与 start/update 角色；start/update 折叠 State，buildLocationData 可向 Turn/Step 发布自有数据，buildViewNode 则为一个 target 生成最终 Node。

contiguous SessionEvent window
        │ match(event) → {kind, id, role}
        ▼
Context(kind:id): start + ordered updates + State
        │                  │
        │                  └── Location index: Session / Turn / Step
        ▼
target-specific stable Node ──► chat / trajectory / other view builders

replaceWindow 留给完整 open/resync/gap repair 与低频 registry rebuild。普通 append 不扫描旧 Context：只更新 location boundary、匹配这一个 input，并重放真正受依赖变化影响的 Context；prepend 只收集新旧页中的 fresh events，刷新改变 location 的 matches，再重放 affected closure。同一个 event 可被多个 Definition 接纳；fallback 仅在没有普通 Definition 匹配并认领同一 target 时运行。Context key 是 kind + id；重复 start，或在日志顺序中位于 start 之前的 update，都会失败。Definition 返回不稳定 view key 或错误 target 同样会失败。

Location index 重建时保留未变化 Turn/Step 对象的引用，并返回 location 改变的 seq 集合；live 非边界 append 只记录当前坐标，边界 append 只重访所属 Turn 的 seq。因此历史分页可以补齐更早的 start 或 predecessor，又不必让所有可见 Node 更换 identity。

14. Tool 呈现：递归拓扑归 runtime，原子外观按 wire name 分派

ui-tool 先以 tool-call key 占据 conversation.chat.node，并在同一次注册中声明 session-scoped keyed child tool.call.toolview；随后 shell、read、mutation、search、web、todo、question 等视图各自注册。原子视图的 owner payload 只包含 call id、wire tool name、冻结的 running/settled block、cwd，以及 Host-bound openFile 与 local inspect callback；框架仍按 session scope 注入 standard kit，registrant 也可加入自己的 inject share。它不负责遍历 root/subcall 拓扑，也不重新配对事件。

ToolCallTree 对根 call 与每层 subCalls 走同一 keyed dispatch，entryKey 就是 wire tool name；无注册者时回退 GenericToolCard。generic renderer 选择 terminal/read/diff/search/web card。其纯模型从冻结 slice 派生 variant、lifecycle、summary、path 与 input/output；专用 keyed registrant 命中时直接替换这一 fallback，而不是在通用卡片外再叠一层。

推论

扩展一个新 Tool UI 的最小面是“注册 wire name 对应的原子 renderer”。Session 事件配对、Code Mode 子调用树与 ChatFlow 位置仍由上游投影拥有，避免每个业务插件各自实现一套 transcript parser。
